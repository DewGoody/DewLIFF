# Config Playground — Concept สำหรับออกแบบ

เครื่องมือนี้ไม่ใช่ admin UI ของลูกค้า — เป็นเครื่องมือสำหรับ **เรา** ใช้ตั้งค่าแคมเปญ

---

## ปัญหาของเวอร์ชันแรก

- โยน field ทั้งหมดมากองรวม ไม่รู้ว่าต้องเริ่มจากไหน
- ไม่เห็นว่า "อะไรสัมพันธ์กับอะไร" — ตั้ง axis แล้วมันไปอยู่ตรงไหนในคำถาม? ไปอยู่ตรงไหนในผลลัพธ์?
- Simulator แยกจาก form → ต้องกดสลับแท็บไปมา
- ไม่มี "ภาพรวม" ให้ดูทั้งระบบพร้อมกัน

---

## Mental model ที่ถูกต้อง

ทั้งระบบคือ **ท่อ 3 ชั้น** ที่ไหลจากซ้ายไปขวา:

```
แกนบุคลิก           คำถาม              ผลลัพธ์
───────────        ─────────          ──────────
สายลุย        ←──  ตัวเลือก A (+2)    fire+fire → ไฟลุก
สายนิ่ง       ←──  ตัวเลือก B (+2)    fire+calm → คันเร่ง+เบรก
สายละเอียด    ←──  ตัวเลือก C (+2)    calm+calm → นิ่งคูณสอง
                                      ...
                                      ไม่ตรงเลย → สายกลาง (fallback)
```

**คนตั้งค่าต้องเข้าใจ 3 อย่างนี้เท่านั้น:**

1. **แกน** คืออะไรบ้าง (personality dimensions)
2. **คำถาม** แต่ละตัวเลือกให้คะแนนแกนไหน
3. **ผลลัพธ์** คู่แกนไหน + แกนไหน = ได้ผลอะไร

ส่วนอย่างอื่น (brand, copy, rules) เป็นของที่ตั้งครั้งเดียวแล้วแทบไม่ต้องแก้

#### โหมด 1: ตั้งค่า — หน้าเดียวไหลลงเป็น step

ไม่ใช่แท็บ แต่เป็น **section ที่เรียงกัน** แบบ scroll ลงไปเรื่อย ๆ
พร้อม sidebar ที่แสดงภาพรวมตลอด

```
┌─ Sidebar (fixed) ──────┬─ Main ─────────────────────────────┐
│                        │                                     │
│  ┌──────────────────┐  │  STEP 1: ตั้งแกนบุคลิก              │
│  │ ภาพรวม           │  │  ──────────────────────────          │
│  │                  │  │  ┌────────┐ ┌────────┐ ┌────────┐   │

│  │ │ 🔥🧊🎯       │ │  │  STEP 2: เขียนคำถาม                 │
│  │ │🔥 ✅ ✅ ✅    │ │  │  ──────────────────────────          │

│  │ │🎯 ✅ ✅ ✅    │ │  │  │ ข้อ 1: เช้าวันจันทร์...        │    │

│  │ หรือ             │  │  │ ข้อ 2: เจอปัญหาใหม่...        │    │
│  │ ✕ ขาด 2 อย่าง   │  │  │ ...                          │    │

│                        │                                     │
│  [ ▶ ลองเล่น ]        │  STEP 3: ตั้งผลลัพธ์                │

│                        │  ┌─── สายลุย + สายลุย ───────────┐   │

│                        │  └───────────────────────────────┘   │

│                        │  ┌─── สายลุย + สายนิ่ง ──────────┐   │

│                        │  │ "คนหนึ่งดันให้ไปข้างหน้า..."    │   │

│                        │                                     │
```

**ทำไมต้องเรียงแบบนี้:**

| Step | ทำอะไร | ทำไมต้องก่อน |
|------|--------|-------------|
| 1. แกน | ตั้งแกนบุคลิก | คำถามต้องรู้ว่ามีแกนอะไรบ้างถึงจะตั้ง scores ได้ |
| 2. คำถาม | เขียนคำถาม + ตัวเลือก + scores | ผลลัพธ์ต้องรู้ว่ามีแกนอะไรบ้าง (จาก step 1) |
| 3. ผลลัพธ์ | ตั้งว่าคู่แกนไหน = ผลอะไร | ใช้แกนจาก step 1 |
| ⚙️ เพิ่มเติม | brand, copy, rules | ไม่จำเป็นต้องทำก่อน สามารถ collapse ได้ |

---

### Key design: scores ใน step 2 ต้อง visual ไม่ใช่ตัวเลข

แทนที่จะเป็น input box ตัวเลข:

```
❌ แบบเดิม (งง):
   energy:  [ 2 ]
   calm:    [ 0 ]
   precision: [ 0 ]

✅ แบบใหม่ (เห็นปุ๊บเข้าใจ):
   สายลุย     ●●○○○      +2
   สายนิ่ง     ○○○○○       0
   สายละเอียด  ○○○○○       0

   หรือแบบ slider:
   สายลุย     ◄──────●──► +2
   สายนิ่ง     ◄──●──────►  0
```

กดวงกลมเพิ่ม/ลดคะแนน -5 ถึง +5

---

### Key design: ผลลัพธ์ใน step 3 แสดงเป็น grid ไม่ใช่ list

```
❌ แบบเดิม (ต้องจำว่า pair อะไรคืออะไร):
   code: fire_fire
   pair axis 1: [energy ▾]
   pair axis 2: [energy ▾]

✅ แบบใหม่ (เห็นภาพทันที):
                สายลุย      สายนิ่ง      สายละเอียด
   สายลุย      [ไฟลุก 🔥]  [คันเร่ง⚡]   [ลุยมีแผน📋]
   สายนิ่ง      ─────────   [นิ่งx2 🧊]   [นิ่งลึก 🌊]
   สายละเอียด   ─────────   ─────────    [ละเอียดยิบ🎯]

   ⬇ ไม่ตรงเลย → สายกลาง (fallback)
```

- กดช่องไหน → เปิด form แก้ title, body, รูป ของผลลัพธ์นั้น
- ช่องที่ยังไม่ได้ตั้ง → แสดงเป็น "+" ให้กดเพิ่ม
- ตาราง 3×3 แสดงครึ่งบน (สามเหลี่ยม) เพราะ A+B กับ B+A ผลเหมือนกัน

#### โหมด 2: ลองเล่น — จำลองหน้า LIFF จริง

```
┌─ Phone frame ──────────┬─ Panel ─────────────────────────────┐
│                        │                                     │
│  ┌──────────────────┐  │  Player A                          │
│  │                  │  │  ─────────                          │
│  │   คู่หูสายไหน      │  │  สายลุย     ████████░░  8         │
│  │                  │  │  สายนิ่ง     ██░░░░░░░░  2         │
│  │   ตอบ 5 ข้อ       │  │  สายละเอียด  ░░░░░░░░░░  0         │
│  │   แล้วส่งให้เพื่อน  │  │  แกนเด่น: สายลุย                  │
│  │                  │  │                                     │
│  │  ┌────────────┐  │  │  Player B                          │
│  │  │  เริ่มตอบ   │  │  │  ─────────                          │
│  │  └────────────┘  │  │  (กด "ลองกับคู่หูตัวอย่าง"           │
│  │                  │  │   หรือตอบเองเป็น B ได้)               │
│  │  ลองกับคู่หูตัวอย่าง│  │                                     │
│  │                  │  │  ─────────                          │
│  └──────────────────┘  │  ผลลัพธ์: (รอทั้งคู่ตอบ)              │
│                        │                                     │
└────────────────────────┴─────────────────────────────────────┘
```

**สิ่งที่ต่างจากเวอร์ชันแรก:**

1. เล่นได้ทั้ง A และ B ในหน้าเดียว
   - กดตอบเป็น A → เห็น scores A
   - กด "ลองกับคู่หูตัวอย่าง" → demo buddy ตอบอัตโนมัติ → เห็นผลทันที
   - หรือกด "ตอบเองเป็น B" → ตอบอีก 5 ข้อ → เห็นผลทันที
2. phone frame ใช้สี + ข้อความจาก config จริง (preview ได้เลย)
3. panel ขวาแสดง scores สดระหว่างตอบ
4. พอตอบครบ → แสดง result card เหมือนหน้า LIFF จริง

## สิ่งที่ซ่อนได้ (ไม่ต้องเห็นตลอด)

| อะไร | ซ่อนไว้ไหน | เปิดดูเมื่อไหร่ |
|------|-----------|--------------|
| Brand (ชื่อ, สี) | ⚙️ ตั้งค่าเพิ่มเติม (collapsed) | ตอนอยากเปลี่ยนธีม |
| Copy (ข้อความ 20+ ตัว) | ⚙️ ตั้งค่าเพิ่มเติม (collapsed) | ตอนอยากแก้ข้อความ |
| Rules (TTL, limits) | ⚙️ ตั้งค่าเพิ่มเติม (collapsed) | แทบไม่แก้ |
| Messages (push templates) | ⚙️ ตั้งค่าเพิ่มเติม (collapsed) | แทบไม่แก้ |
| Raw JSON | ปุ่ม "ดู JSON" เปิดเป็น drawer/modal | ตอน export หรือ debug |

## สรุปหลักการออกแบบ

1. **ไหลเป็น step** ไม่ใช่ tab — คนเห็นลำดับว่าต้องทำอะไรก่อน
2. **Sidebar แสดงภาพรวมตลอด** — matrix + validation status
3. **Scores เป็น visual** ไม่ใช่ตัวเลขในช่อง — กดเพิ่ม/ลด
4. **ผลลัพธ์เป็น grid** ไม่ใช่ list — เห็นทุกคู่พร้อมกัน กดช่องแก้ได้
5. **ซ่อนของที่ไม่ต้องแก้บ่อย** — brand, copy, rules อยู่ใน collapsed section
6. **Simulator อยู่ในโหมดแยก** — เล่นได้ทั้ง A+B, preview ด้วย theme จริง
7. **Validate สด** — sidebar บอกตลอดว่ายังขาดอะไร ไม่ต้องกดปุ่มเช็ก
